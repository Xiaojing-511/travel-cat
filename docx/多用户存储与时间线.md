# 多用户存储与时间线

环境 ID：`cloud1-4grqnt5f5b5d8f20`

## 原则

- openid 只在云函数里从 `wxContext` 读取，游戏只认 `userId`。
- 时间以云函数 `Date.now()` 为准。客户端倒计时用上次 `serverNow` + 单调钟插值。
- 云端不实时推猫，打开或操作时追赶时间线。
- 无网展示缓存，喂食 / 追赶 / 欢迎回家不落地。

## 集合

- `users`：`_id = userId`，`openid` 唯一。
- `players`：`_id = userId`，时间线、库存、`hasUnreadCard`、`lastCardTemplateId`、`cardCount`、`rev`。
- `cards`：每张明信片一条，`userId` + `collectedAt`。

客户端对三张表都应 `read: false`、`write: false`，只走云函数 `player`。

## 云函数 `player`

`event.action`：`ensureDb` / `login` / `sync` / `feed` / `welcomeHome` / `clearUnread` / `hide` / `listCards`。

部署前执行 `npm run after-edit`（测试 + 打包旅行图 + 把 `game.js` / `trips.js` 拷进云函数）。不要手改 `cloudfunctions/player/utils/game.js`。

## 旅行图

实拍在云存储 `trips-upload/{templateId}.jpg`，前缀：

`cloud://cloud1-4grqnt5f5b5d8f20.636c-cloud1-4grqnt5f5b5d8f20-1302940040/trips-upload/`

`trips.js` 用完整 `imageFileID`。包内只留 UI 和 `trip-mock.jpg`。旅行原图、原始背景 PNG、BGM 原文件由 `packOptions` 排除。

本地压图并写回 fileID：`npm run after-edit`（或单独 `npm run upload-trip-images`），再到开发者工具把 `tmp/trips-upload` 传到云存储目录 `trips-upload/`。

BGM 走云存储 `audio/bgm.mp3`。压缩资源：`npm run compress-assets`，再把 `tmp/audio-upload/bgm.mp3` 传到该目录。

## 开发者工具

1. 开通该环境，上传并部署云函数 `player`（先装依赖 `wx-server-sdk`）。
2. 调用一次 `ensureDb`，或在控制台建 `users` / `players` / `cards`。
3. 给 `users.openid` 加唯一索引；`cards` 加 `userId` + `collectedAt` 降序。
4. 三集合权限对客户端关闭。
5. 真机或模拟器登录后冷启动、杀进程再开、改系统时间、无网喂食。
